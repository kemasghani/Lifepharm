# Lessons Learned

Every time something cost us time, it goes here once, as a rule. This is the project's learning record: read the section for the area you are about to touch.

**Format:** `L-NNN · date · Symptom → Cause → Rule · Enforced by`.
"Enforced by" says whether a machine checks it (`init.sh`), a doc reminds us, or nothing yet. **If a lesson is hit twice, promote it to a check** in `tools/harness/check_theme.py`.

Add new lessons at the end of their section with the next free number.

## A. Shopify sync and deploy

- **L-001** · 2026-11-10 · Template edit never appeared on the draft → a JSON template held more than 25 sections; Shopify rejects the whole file **silently** → keep templates at 25 sections or fewer; product templates sit at 20 to 23, so remove disabled legacy sections before adding. · `init.sh` (FAIL above 25, WARN at 24).
- **L-002** · 2026-11-10 · Same silent rejection → one setting outside its schema range (`input_border_radius` max 10) → validate every range, select and checkbox value against its schema. `shopify theme check` does not catch this. · `init.sh` (range/select/checkbox checks on templates, section groups, settings_data).
- **L-003** · 2026-11-10 · Template rejected → empty image or url values written as `""` → omit the key instead of writing an empty string. · doc.
- **L-004** · 2026-11-11 · A "disabled" app section in a section group kept rendering → Shopify drops `disabled` on app sections inside groups → remove the app section from the group instead. · doc.
- **L-005** · 2026-11-14 · Second of two quick pushes never reached the draft → Shopify's GitHub sync applied the first and skipped the second → leave a minute between pushes; confirm with the Admin API `theme(id:).files(filenames:)` before assuming a rejection. · doc.
- **L-006** · 2026-11-10 · curl on the preview showed the live theme → `preview_theme_id` needs a cookie jar, and the first answer is a 302 → `curl -L -c jar -b jar "...?preview_theme_id=..."`; poll for a marker string, sync takes 1 to 10 minutes. · doc.
- **L-007** · 2026-11-18 · US/EU pages showed only a title → branches started as a UK copy and lacked live-only templates → after creating a store branch, run `tools/store-audit/port_templates.py` (read-only on live, never overwrites). · doc.
- **L-008** · 2026-11-20 · Referral attributes differed between draft and live → US/EU drafts lacked the Teqnavi app embeds → any branch sync must keep each store's own app embeds (`sync_branch.py` does). · doc.
- **L-058** · 2026-11-23 · `sync_branch.py us` would have rewritten 27 data files (index, FAQ pages, product templates) for a five-file code change, because the US branch has moved on from master's data since the last full sync → for a code-only change, first confirm the touched files are identical on the store branch and on master before the change (`git diff <store> master~1 -- <file>`), then `git checkout master -- <those files>` on the store branch; keep `sync_branch.py` for a deliberate full resync. A theme setting that is one store's own choice must be listed in `STORE_SETTINGS` there, or a full sync resets it. · this file.

## B. Liquid, CSS and JS

- **L-010** · 2026-11-18 · `class` silently missing on images → a filter inside `image_tag` arguments (`alt: x | default: y`) drops the other args → assign first, then pass the variable. · doc.
- **L-011** · 2026-11-12 · Variant image script compared the wrong id → the product form has an input named `id`, so `form.id` and `detail.formId` return an element → use `form.getAttribute('id')`. · doc.
- **L-012** · 2026-11-18 · Page froze after a referrer was set → a MutationObserver wrote text into the subtree it watched → never write DOM unconditionally inside an observer on the same subtree; compare first. · doc.
- **L-013** · 2026-11-18 · Share Your Cart stopped working after a quantity change → its jQuery handler was bound to the element, which the drawer re-render replaces → delegate events from a stable ancestor. · doc.
- **L-014** · 2026-11-11 · Quick add did not update the drawer → the request must bundle the theme's cart sections like the theme does → reuse the theme's section-rendering list. · doc.
- **L-015** · 2026-11-18 · Button styles ignored → Impact's button reset beats plain class selectors → style as `button.x:not(#lp-none)`. · doc.
- **L-016** · 2026-11-17 · News styles missing on some pages → Dawn loads a section's `{% stylesheet %}` only where that section renders; Dawn's root is 62.5% → shared styles go in `assets/lp-news.css`; scale rem by 1.6. · doc.
- **L-017** · 2026-11-18 · Odd character in About copy → merchant text contained a hidden `\x03` → strip control characters when pasting client copy. · doc.
- **L-057** · 2026-11-22 · Filter sheet closed and chips jumped after every choice → the theme's `facet:update` replaces every child of the section (DOMParser, then replaceChildren), so an open dialog, scroll positions and focus are gone, and `<noscript>` content comes back as real elements → keep that state in JS and restore it in a MutationObserver on the section (`initFilterBar` in `assets/lp-premium.js`). · doc.
- **L-060** · 2026-11-23 · A link written as `/products/x#anchor` reached the page as `/products/x#anchor?ref=retaildirect` → the Teqnavi referral app appends `?ref=` to the end of every internal link, after any hash, which breaks both the anchor and the parameter → do not put a `#anchor` on an internal link in theme code. · this file.
- **L-061** · 2026-11-23 · New list styling in the buy-box dropdowns lost to square bullets and a 1.4em row gap → most product templates carry merchant `custom_css` on the main-product section, and Shopify scopes it with the section id, so it beats any class selector → check `custom_css` in the template JSON when a rule "does not apply"; `!important` is the honest fix for shared code that must look the same on every template. · this file.
- **L-062** · 2026-11-23 · A new block type between two dropdowns produced a gap and a doubled rule → Impact groups consecutive `collapsible_text` blocks into one `.accordion-group` in `snippets/product-info.liquid`, by block type → a block that renders an accordion must be added to that grouping condition (`lp_dropdown_types`). Also: `height: 100%` on an image inside a `display: grid` box with an auto row is ignored (the photo was cropped); use a block box. · this file.
- **L-063** · 2026-11-23 · An icon beside 14px Metropolis looked low although the flex row was centred → the font's caps sit above the line box centre and a hand-drawn SVG was not centred in its viewBox → measure the ink (screenshot at 4x, compare the icon's rows with the first glyph's rows) and nudge by the measured amount; `tools/qa` checks cannot see this, a person or a pixel measure can. · this file.
- **L-064** · 2026-11-23 · "Pairs Well With" vanished after its quick-add drawer was opened and closed → the drawer loads another product's whole buy box inside the block, and a `.product-info__block-item:has(...)` rule meant for one small block then matched the outer block too → a `:has()` rule on `.product-info__block-item` must name the block (`[data-block-type=...]` or `[data-block-id=...]`), because quick-add nests a second buy box inside the first. Check: `tools/qa/pdp_quick_add_check.py`. · this file.
- **L-065** · 2026-11-23 · In the Stamped widget the reviews stayed on screen above the questions after the Questions tab was pressed → Stamped hides the list with an inline `display: none`, and our `display: grid !important` on `.stamped-reviews` overrode it → when a third-party container gets a forced `display`, add the matching `[style*="display: none"] { display: none !important }` rule, and test every state the widget has (both tabs, both forms), not only the first paint. Check: `tools/qa/pdp_reviews_tabs_check.py`. · this file.
- **L-066** · 2026-11-23 · The size card said "$1.52 per capsule" and "Save $64" while the sticky bar said "In stock" and the button showed no saving → three places each parsed the size name and priced the saving on their own (size card, sticky bar, button), and only one knew the Family Pack rule → a value shown in more than one place comes from one snippet (`lp-variant-units`, `lp-variant-reference`); the plan picker is a theme asset (`assets/skio-plan-picker-component.js`), so it can read the same value through a data attribute. Check: `tools/qa/pdp_price_consistency_check.py`. · this file.

## D. QA and verification

Leave quoted study titles, form labels, sentences and metafield text alone. · doc (candidate for a scripted sweep, see tech debt).
- **L-031** · 2026-11-11 · 390px screenshots were wrong → headless Chrome `--window-size` renders too wide → use Playwright with `channel="chrome"`, `wait_until="load"`, never `networkidle`. · doc.
- **L-032** · 2026-11-18 · Storefront started answering 429 and a Cloudflare challenge → heavy Playwright runs against uk/shop domains → use the Admin API for ids and data; keep browser runs short. · doc.
- **L-033** · 2026-11-11 · Console errors blamed on the theme → `e is not a function` comes from Stamped.io; `addEventListener` null on /collections/all also happens on live → compare with the live theme before fixing "our" error. · doc.
- **L-035** · 2026-11-21 · Full QA crawl got the IP a Cloudflare challenge (429) for ~30 min on uk.lifepharm.com, and EU's cart API returned 429 mid-run → crawl one tab at a time with delays (`tools/qa/site_qa.py` does), light HTML checks for same-template pages, and pace cart-heavy E2E runs. · `tools/qa/`.
- **L-034** · 2026-11-12 · Done claimed before the draft had synced → always verify on the draft preview at 390px and 1440px: no horizontal scroll, no new JS errors. · CLAUDE.md section 1, `init.sh` reminder.
- **L-056** · 2026-11-22 · Menu "Nutritionals" showed one product, "Shop best sellers" opened a category, UK "View all FAQs" opened the US store → nobody had read each label against its destination (a menu item saved with a tag filter, store addresses hard-coded in templates and metafields) → after link or menu work run `tools/qa/collection_filters_check.py` on each store and read the links block. · tool.
- **L-069** · 2026-11-24 · A crawl-style QA report listed twelve findings and four were not defects: the store-wide "1,100+ reviews" line and a pack's "Includes IMMUNE+++ (20 reviews)" are D-065, the Facebook and LinkedIn links pointing to "#" were the Share Your Cart dialog's (filled when the share link exists), and filter chip counts are Shopify's per-value counts, so a product that matches two values makes them add up to more than the total → trace every finding to its source file and its decision before changing anything, and report the ones that are by design as such. · this file.
- **L-070** · 2026-11-24 · Two QA runs reported broken pictures "from the US store" and empty picture addresses on product pages → none were theme or store files: every one sat in `.stamped-review-product`, a thumbnail Stamped hides with `display: none` and loads anyway, with the address it saved when the review was written → before fixing a broken picture, find the element it sits in; a third-party widget's saved address is fixed in that app or rewritten by script, not by uploading files. Check: `tools/qa/broken_images_check.py`. · this file.
- **L-074** · 2026-11-24 · Press logos and science images had no `alt` attribute at all → `image_tag: alt: image.alt | default: name` does not work: a filter cannot sit inside another filter's arguments, so the `default` applied to the whole tag and `alt` stayed nil → assign the alt text to a variable first, then pass the variable. · this file.
- **L-075** · 2026-11-24 · After a day of browser checks, Lighthouse runs and crawls the storefronts stopped answering this machine, and three checks died mid-run → Shopify limits an address that asks too much → run the long checks once per batch, not after every small push, and keep runs for one store at a time. A fix that touches a third-party widget (Stamped) is tested with the local file served in place of the deployed one before it is pushed. · this file.
- **L-076** · 2026-11-25 · PageSpeed Insights on `staging.lifepharm.com/products/laminine` reported "ARD manifest is invalid: Unexpected token '<'" → the staging store is password-protected, so every address, `/.well-known/ard.json` included, answers 200 with the password page; Lighthouse only runs that audit when the address answers 200, and a live store answers 404 there, so the audit does not apply → a PageSpeed or Lighthouse report of a password-protected store describes its password page, not the page in the address. Measure the redesign on a real store with the draft preview address (`https://shop.lifepharm.com/<path>?preview_theme_id=<id>`). Do not add an agent catalog to make the audit pass: it is only for sites that have agent resources to list. · this file.
- **L-077** · 2026-11-25 · A preload header for a responsive image looked right and did nothing, or fetched a second file → four things, each measured on the staging store. (1) Chrome evaluates the header's `imagesizes` before the phone viewport applies: the phone still counts as 980px wide, so `vw` lengths and `min-width` conditions pick the wrong candidate, even with the viewport tag first in `<head>`. Device width (`min-device-width`) and pixel density are right at that moment. (2) Shopify adds an image to the Link header only when `image_tag` builds the srcset itself (`widths`); with a custom `srcset:` the header entry disappears without a warning. (3) The srcset from `widths` stops at the width of the `image_url` it is given, so `image_url: width: 800` caps the ladder at 800. (4) Cloudflare repeats the header in a 103 early hint without quotes, the commas inside `imagesizes` and `imagesrcset` break it, and Chrome ignores that entry: an image hint works from the final response only, a stylesheet or font hint from the early hint. Also: a fixed length times the pixel density must not land one pixel above a candidate (267px at 3x is 801 and picks the 1000px file while the hint took 800). → put `preload: true` on the real `<img>`, give it lengths that do not depend on the viewport, and let a `<source>` take every device that must not use it. Check with a request log on several devices that each one fetches exactly one hero file (scratch script; make it a tool if this is needed a second time).
- **L-078** · 2026-11-25 · A PageSpeed score of 68 was read as "the page is heavy" → the score is built from simulated metrics, and the simulation starts from what the lab browser observed. In that run every stylesheet and the hero had arrived by 0.7 s, but the first paint was observed at 2.4 s with the main thread idle, and the report carried the warning "The page loaded too slowly to finish within the time limit". No code that hides the page was found and it could not be reproduced (first paint 0.5 to 0.6 s here, also with a 4x slower CPU). A late observed paint pulls every request that finished before it into the simulated LCP, which is how 7.4 s came out. → read `observed` next to the metrics (`tools/perf/psi_run.py --report <link>` prints both), compare medians of several runs (`tools/perf/lh_run.py`), and do not act on one run. The PageSpeed API and its page both refuse new runs from this network once the anonymous quota is used up; a report someone else ran can still be read from its link.
- **L-079** · 2026-11-25 · PageSpeed's "Render-blocking requests" listed four stylesheets in `<head>` and "Reduce unused CSS" said 81 KB → neither was what held the hero. The four are sent as early hints to real visitors and one stylesheet serves every page, so "unused on this page" is expected; deferring them would trade a number for a flash of unstyled content. What did hold the paint was a 2 KB stylesheet printed by an app block at the start of `<body>`, listed only under "Show 3rd-party resources". → for an LCP problem, list what finished between the observed first paint and the observed LCP in the report's raw data, and look for a stylesheet in `<body>`; treat the insight list as a list of candidates. Same report: "fetchpriority=high should be applied to the image preload request" was true and could not be fixed where the hint was (Shopify's Link header), only by moving the hint into the HTML (D-085).
- **L-080** · 2026-11-25 · A hidden loader with an endless CSS animation kept the product page restyling 60 times a second, unseen → `opacity: 0` does not stop an animation. Scope loader animations to their busy state and check `document.getAnimations()` for endless ones. Also: the Admin API can return the previous theme file for some seconds after an upsert; read again before concluding that a change or a restore failed.
- **L-081** · 2026-11-25 · The theme check reported 0 errors against a baseline of 13 → it had crashed out of memory on 262 MB of PageSpeed reports under `tools/perf/reports/` (git-ignored, still read), and the ratchet read empty output as zero. It now fails when the checker does not run, and gives it a larger heap. A number that is suddenly better deserves the same look as one that is worse.
- **L-082** · 2026-11-26 · Homepage counters showed "-2,635 days": the count-up used performance.now() as its start while requestAnimationFrame passes the frame's own time, which can be older when a tab was held back, so the elapsed time was negative → take the start from the first frame and clamp at 0. · `assets/lp-premium.js`
- **L-083** · 2026-11-26 · Removing the last buttons of a drawer also removed its only visible way out: the theme hides the header, and the close button with it, when the header slot is empty → after taking controls out of a drawer, check the close button and the focus. Check: `tools/qa/quick_add_drawer_check.py`. · this file
- **L-084** · 2026-11-26 · Stamped matches a badge by product id, so staging (new ids) shows lower counts than the real stores for some products; compare stores on their own badges, never staging against live. · this file
- **L-085** · 2026-11-26 · The US and Europe drafts ran without Klaviyo, Clarity, NoFraud, Selleasy, UpPromote and others, with the UK's Stamped account and consent rules, and US product pages without the IBO price → branches were built from the UK theme and only the Teqnavi embeds were restored (L-008 again) → run `tools/store-audit/app_parity.py` after every branch port. Check: that script (exit 1 on a gap).
- **L-086** · 2026-11-26 · "IBO" was taken from a storefront script that treats types 2 and 3 alike for referral links; counting real customers showed type 2 is not IBO on the US → check a business rule against the data before it gates anything. · this file
- **L-087** · 2026-11-26 · The US Earn page lost its text: the live theme's section had an extra setting the redesign's section lacks, and Shopify silently drops values for settings a schema does not declare; also, GitHub sync only re-reads files that changed, so fixing the schema alone did not bring the values back → when a section's schema changes, check `lost_settings.py` and touch the templates that hold the values. Check: `tools/store-audit/lost_settings.py`. · this file
